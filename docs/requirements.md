# MyHealthLog 要件定義書

## 1. プロジェクト概要
オムロンの体組成データと自作の献血ログを統合・分析・可視化する、Rust製のローカル完結型デスクトップアプリケーション。

## 2. 核心的価値
- **4時間ウィンドウ最適化**: 1日のうち最も測定密度の高い4時間を自動抽出し、測定条件を平準化する。
- **統合分析**: 体組成と血液検査結果（肝機能、赤血球等）の相関を同一時間軸で可視化する。
- **スタンプラリー要素**: 献血場所や種別を記録し、将来的なロケーション管理の基盤とする。

## 3. 機能要件
### 3.1 データ管理
- **インポート**: オムロンCSV、自作献血ログCSVのパース。
- **手入力**: GUIからの直接入力（CSVより優先される `Manual` フラグ付き）。
- **永続化**: SQLite + Dieselによるローカル保存。

### 3.2 可視化・UI
- **タブ切り替え**: 体組成、バイタル、肝機能、赤血球、白血球/血小板の5グループ。
- **動的プロット**: `yyyymmdd` 指定による期間変更、マウスによるズーム・スケーリング。
- **基準値表示**: 日本赤十字社の基準値をグラフ背景に帯状（シェーディング）表示。
- **データ一覧**: 献血場所や種別を含めた全データのスプレッドシート表示。

## 4. 非機能要件
- **拡張性**: 地図API連携を見据えたデータ構造。
- **保守性**: クリーンアーキテクチャによる依存関係の分離。
